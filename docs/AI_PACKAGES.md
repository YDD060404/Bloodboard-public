# Large AI files and packages (V7-01 / V7-07) — status

**Implemented now:** the arbitrary ~400 KB AI import ceiling is gone. A single AI file (`.json` parameter file or `.js` strategy module) is accepted up to a **resource guard of 192 MiB**; files above **8 MiB** are marked "large" in the AI list (loading into each worker takes longer). Sizes are reported, not hidden (`CoachEntry.resource`). Import works by the Import button (browser), by dropping the file on the window (browser and Mac app for `.json`; `.js` modules in the Mac app are copied into the AI folder by hand — the app stores modules as files), and by the AI folder itself.
Distinguish the limits: *file size* (guard above), *memory* (each worker loads its own copy of a module: N workers ≈ N × size), *model context* (provider side, unrelated) and *decision time* (one configurable budget ≤ 60 s total).

**Not implemented yet (so nothing here is a promise):** a multi-file *package* (module + separate weight files with a manifest listing sizes and SHA-256), drag-and-drop of such a package, per-worker memory accounting and a shared weight loader, and the Match Lab loading a package. Weights today must be embedded in the single module file. This is carried in the acceptance matrix as the remaining part of V7-01 and V7-07; it will be designed together with the neural-checkpoint contract (SPATIAL-*) once the original checkpoint materials are available — a format invented without them would have to be redone.
