# Bloodboard 7.0.1 — local installation, one shared AI folder, High Elf

7.0.1 follows the delivered 7.0.0 (kept as the rollback). It is not a statement that every V7 requirement is complete.

## What changed
1. **Local installation and safe retirement** (`install_bloodboard.sh`, `retire_obsolete.sh`, `docs/LOCAL_INSTALL.md`). The installer verifies `SHA256SUMS` and `MANIFEST.json`, installs V7 beside the previous install (rollback kept), updates only the Match Lab code (after a tar.gz backup), checks the web build, the engine/rules/API hashes, the runner fingerprint and the 120 000 ms ceiling, smoke-tests the bridge (403 unpaired, authorised version), builds the native app when Command Line Tools exist, snapshots user data before and after, and writes a report. The retirement tool inventories, archives with a SHA-256 manifest, and only moves (never deletes) after confirmation; protected paths (Application Support, Claude data, CloudDocs, `.git`, Match Lab user data, Hopeful baselines, V5.8, the V7 install) are never touched.
2. **Build identity**. The game home screen and the Match Lab show `Build 7.0.1 · engine … · rules … · API …`; the Lab runner has a `fingerprint` command and the Lab a `/api/build` endpoint. `scripts/build-line-flow.mjs`.
3. **One shared AI folder**: `~/Library/Application Support/Bloodboard/AI/` for the native app, online-coach installer, coach loader and Match Lab (`docs/AI_FOLDER.md`). One resolution policy (`online/aidir.mjs`, shipped byte-identically as `match-lab/aidir.mjs`), no silent fallback, credentials kept in `Bloodboard Online`. Copy-only, idempotent migration of `Bloodboard V6/AI`, `Bloodboard Endgame Workshop/AI` and other version-specific folders: verified backup first, dedupe by SHA-256, conflicts preserved separately, credential-like files not copied. Menu "Choose AI Folder…" is the supported selection flow. "Show AI Folder", drag-and-drop import, generated online coaches, the installer and the docs now point at the shared folder. The game exposes what it loaded with SHA-256 for verification.
4. **High Elf** (`docs/HIGH_ELF_ADJUDICATION.md`): the 2026 table (Lineman, Phoenix Warrior, Dragon Prince, White Lion) with the two disputed fields decided from named evidence (Lineman Secondary S; Dragon Prince keywords Elf, Blitzer, Runner). Old positions are retired, not deleted: saved teams still load, new hiring and the tournament/Sevens validators say explicitly that they are retired. This is an adjudication, not an official erratum; each value is one data line.
5. English-only package; English translations of the Chinese planning and integration documents were prepared beside the originals in your BB folder (not part of this package).
